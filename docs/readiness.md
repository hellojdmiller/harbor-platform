## Release acceptance sequence

1. Create a production-like isolated environment with fictional accounts, production-equivalent identity controls, and separate provider credentials.
2. Sign in as two unrelated users and an administrator. Attempt every cross-workspace and cross-owner read/write. Deny access without exposing existence or content.
3. Submit a task; observe durable state and generated response in a second browser. Refresh, disconnect and reconnect. Confirm exactly one logical task and conversation.
4. Prepare an email; inspect exact recipient, subject and body. Approve it. Match the persisted provider ID with the provider dashboard and signed delivery event. A submitted request is not a verified delivery.
5. Interrupt requests before and after dispatch, cancel during work, expire an approval, reduce a budget and suspend a membership. Confirm fail-closed behavior, no blind retry, and retained unknown-cost reserves.
6. Revoke source permissions after extraction and after generation. Confirm facts, wiki presentations, messages and later tools cannot retrieve the derived content. Reconcile stale evidence without silently extending retention.
7. Export data/files, restore to an isolated deployment, inspect component state and compare counts/representative hashes. Validate access controls again. Run no external writes from a restored deployment until intents are reconciled.
8. Test rollback with active workflow journals and schema changes. Finish the unresolved gates above before claiming enterprise readiness.
